# ESP32 Shuba Duck Animation

An ESP32-based animated Shuba Duck displayed on a 128x64 SSD1306 OLED using pre-rendered bitmap frames.

This is a personal fun/learning electronics project inspired by Shuba Duck memes and GIFs.

**Project by:** Moontasir Al Mansur

## Project Overview

This is a small ESP32/OLED animation project that plays a pre-rendered duck animation on a 128x64 monochrome SSD1306 display.

The animation consists of:

- 75 pre-rendered bitmap frames
- 128x64 monochrome frames
- Continuous playback
- Approximately 60 ms per frame
- Approximately 16.7 frames per second
- Approximately 4.5 seconds per complete cycle

All animation data is stored in `frames.h`.

## Features

- Pre-rendered duck animation
- 75 bitmap frames
- 128x64 monochrome OLED output
- Continuous frame playback
- Approximately 16.7 FPS playback
- I2C SSD1306 display
- Frame data stored in program memory

- Interface: I2C
- Address: `0x3C`

## Pin Connections

| OLED Pin | ESP32 Connection |
|---|---|
| VCC | Appropriate power connection for the OLED module |
| GND | GND |
| SDA | Default I2C SDA pin for the selected ESP32 board |
| SCL | Default I2C SCL pin for the selected ESP32 board |
| RST | Not connected (`OLED_RESET = -1`) |

Because the sketch does not explicitly assign SDA/SCL GPIOs, the exact pins depend on the selected ESP32 board's default `Wire` configuration.

For a common ESP32 DevKit configuration, the default I2C pins are typically GPIO 21 (SDA) and GPIO 22 (SCL). Verify the defaults for your specific board.

I2C address: `0x3C`

## How It Works

### Initialization

The sketch:

1. Starts the I2C interface with `Wire.begin()`.
2. Initializes the SSD1306 display at address `0x3C`.
3. Stops in an infinite loop if the display initialization fails.
4. Clears and updates the display.

### Frame Playback

The main loop:

1. Iterates through all 75 frames.
2. Retrieves each frame pointer from the `frames[]` array.
3. Clears the display.
4. Draws the frame at `(0, 0)`.
5. Updates the OLED.
6. Waits 60 ms.
7. Continues with the next frame.

The animation therefore loops continuously. The movement is already encoded into the bitmap frames rather than being calculated dynamically. `frames.h` contains the pre-rendered 128x64 monochrome bitmap data.

## How to Build / Upload

1. Install Arduino IDE.
2. Install ESP32 board support if necessary.
3. Install the Adafruit GFX Library and Adafruit SSD1306 (Library Manager).
4. Connect the OLED according to the pin table.
5. Open `ShubaDuck/ShubaDuck.ino`.
6. Select the appropriate ESP32 board.
7. Select the correct COM/serial port.
8. Upload the sketch.
9. The OLED should play the animation.

## Notes / Limitations

- The exact ESP32 variant is not specified in the source project; board selection depends on the hardware you have.
- SDA/SCL use the board's default `Wire` pins; verify them for your board.
- The OLED reset pin is not connected (`OLED_RESET = -1`).
- `frames.h` is auto-generated by an external tool that is not part of this repository.
- The animation is a fixed pre-rendered sequence; there is no input or interactivity.
- Playback uses a blocking `delay(60)` per frame.

## Possible Improvements

- Change playback speed by adjusting `delay(60)`.
- Use non-blocking timing (`millis()`) instead of `delay()`.
- Add a button to pause or switch animations.
- Generate frames at runtime instead of storing pre-rendered bitmaps.
- Use an SPI-based OLED for faster screen updates.
